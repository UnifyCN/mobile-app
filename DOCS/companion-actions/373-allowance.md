# Companion allowance and measurements

The current policy stays at six free generations per UTC calendar day. Premium users remain exempt. The existing generation counter and best-effort failure refund remain the only quota system. No new pricing, allowance, entitlement or reset values are activated.

`get_chatbot_allowance()` is an authenticated, parameter-free read. It derives the owner from `auth.uid()`. It reads `users.is_premium` and `chatbot_usage`. It returns `message_count`, `daily_limit`, `remaining`, `is_premium`, `resets_at`, `observed_at` and the existing `last_message_at`. Premium remaining is null. Reset and observation are server instants. Clients format the instant with the current locale and time zone. They do not compare calendar dates or calculate remaining messages.

A failed read throws. It does not create a zero counter. Query keys contain the account and account epoch. Account cleanup removes allowance reads with other private records. Both clients refresh after successful and failed sends. They also poll the server while mounted. Web main Companion and in-lesson chat use the same allowance read. Mobile has one current Companion generation consumer. No separate Mobile in-lesson generation consumer exists in this checkout.

Drafting, deterministic commands and saved action controls remain available when generation is exhausted. The existing service rejects generation atomically. Its action endpoint does not call the generation gate. Failed sends restore their draft without replacing newer typed text. Existing approval, reminder, receipt and Undo paths remain unchanged.

The new additive migration creates the read and adds `account_allowlist uuid[]` to the existing service-owned feature gate. The empty default keeps the disabled rollout closed. A listed authenticated account can use the existing allowed platforms while the global gate is off. The action handler still enforces version, platform, normal Auth and domain permissions. RAG uses the same account cohort for new context and proposals. Other accounts retain legacy answers and profile grounding. A missing allowlist on an older schema means an empty cohort. The ten deployed action migrations and all old quota RPC signatures remain unchanged. Both repositories contain identical new migration and rollback bytes.

The measurement driver is `unify-front-end/scripts/measure-companion-sessions.py` in Mobile and `scripts/measure-companion-sessions.py` in Web. Use runtime environment variables `COMPANION_API_URL`, `COMPANION_ANON_KEY`, `COMPANION_ACCESS_TOKEN` and `COMPANION_SYNTHETIC_USER_ID`. The ID must match normal Auth. Run only against a disposable synthetic account in the rollout cohort. The driver creates synthetic conversations, messages, one approved task, a direct edit and its recovery receipt. It does not change policy or provider configuration.

Run `python3 scripts/measure-companion-sessions.py --output /tmp/companion-measurements.json --platform web` from Web. Use the equivalent script path in Mobile. Credentials never appear in arguments or output. `--local-controlled` requires loopback and labels fixture cost as controlled. `--model-tier-label` records an explicit operator label. No source default is treated as a deployed model. `resolvedModel` exists only if the provider returned its identity. A configured fallback can still appear in the older `model` field.

The four sessions are planning, task help, deterministic edit and recovery. Generation counts include logical answer and guidance-search requests. They exclude unknown upstream retry attempts. The driver records actual request statuses, sizes, latency, frequency and scope. Existing token/cost metadata describes the answer. Total provider session cost stays unknown when embedding or search cost is unavailable. Fixture costs never become measured provider costs. Useful-session classification requires root review of the actual synthetic outcome.

The saved funnel is `373-funnel.json` with the read-only `373-funnel.hogql` template. Bind the reporting interval and an explicit list of team and synthetic distinct IDs. Keep historical first-event dates outside the report interval filter. The schema accepts only existing categorical action metadata and counts. Review-needed is distinct from a review-screen impression. Lookup is distinct from later-day return or retention. Platform remains unknown if existing captured OS/library properties cannot identify it. The root must verify these properties on the hosted platform before interpreting the report. No hosted analytics configuration changed.

The existing AI generation event now excludes message and answer bodies. It retains categorical and cost metadata. The funnel and generation events must never contain private messages, task titles, reminder notes or saved details. Synthetic fixtures test this boundary. They do not prove production event delivery.

Proposed product decision: retain the current six-per-UTC-day and premium policy until actual provider measurements support a change. Keep the existing default reasoning and model routing. Control cost with all four inputs together: measured model tier, actual effort, requests per session, and scope per request. Use zero unauthorized writes and zero duplicate writes as mandatory stop conditions. Root must select any numerical cost budget, latency threshold or different policy after the hosted measurements. This package activates none of those values.

Root must complete independent review, hosted migration/permission qualification, the account cohort configuration, real provider measurement, native accessibility/input checks and the joint iOS/Android/Web release decision. Native, hosted, provider, ticket and release acceptance remain separate from local checks.
