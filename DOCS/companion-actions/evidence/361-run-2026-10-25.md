### Account-owned call paths (traced before the edits)

One rule now applies on every path: an operation captures its owner (account id and epoch) once, when the user acts, and passes it to every service it calls. Before each request after an `await`, and before each cache or UI write, it checks that the owner is still the established signed-in account. On mobile the session helper treats an unknown account (no subscriber, or a restarted session still being read) as no permission. Services take the owner as a required parameter, so a caller cannot leave it out (the typecheck lists every production caller).

| Stage | Owner captured at | Invalidated by | Guarded side effect |
|---|---|---|---|
| Mobile session helper (`services/account/accountSession.ts`) | `ownAccountWork()` | identity change (epoch+1), sign-out, last subscriber leaves (account becomes unknown) | `stillOwned` needs a known account id equal to the current one and the same epoch; `assertOwned(owner, userId)` also compares the SDK user |
| Mobile send (`useSendMessage`, Companion screen) | send start; the screen sends nothing until the account is known | as above | create, user save, stream, assistant save, streaming bubble, errors |
| Mobile create (`services/companion/createConversation.ts`) | passed in | as above | insert after `getUser`; background `generate-title` invoke; title update; list invalidation |
| Mobile saves (`services/companion/saveMessage.ts`, `useSaveMessage`) | passed in | as above | conversation lookup, insert, context-column retry; optimistic row, rollback and invalidation write nothing once the owner is gone |
| Mobile stream (`utils/gemini.ts`) | passed in | as above | `rag-query` fetch only when the session read names the owner |
| Mobile reads (`useConversations`, `useConversationMessages`) | render snapshot that names the key | as above | list/thread select; a read that loses its owner fails instead of caching another account's rows |
| Mobile task actions (`transport.ts`, `useTaskActions`, `taskActionStore.ts`) | store and read created per owner (account id + epoch) | as above | apply, undo, status lookup and progress read; one operation keeps the client it started with |
| Mobile cache cleanup (`useTaskActionAccountScope`) | account id | account change | removes other accounts' task, Checklist and conversation entries (unchanged) |
| Web session (`lib/accountSession.ts`) | `ownAccountWork()` | `noteAccount` identity change | `assertOwned(owner, userId)`; work started before the account is known has a null owner and makes no authenticated request |
| Web create/save/reply/reads/delete (`services/companion.ts`, `hooks/useCompanion.ts`) | the page or lesson chat passes the owner in the mutation input | as above | insert and untagged retry; lookup, insert and context retry; `/api/companion` reply; list/thread reads; delete; optimistic bubble (not written after an account change during `cancelQueries`); delete rollback and success writes |
