# Companion push worker

Dispatch and enrollment are disabled by default. This service has no automatic Cron schedule. The existing reminder Cron remains the owner of due-event history.

Run one cycle with Deno 2 using `supervisor.ts`. A service manager must start each cycle, record its exit code, and restart failed cycles. The supervisor uses a new process for each dispatch or receipt operation. It kills an operation after four seconds. PostgreSQL 17 independently closes a locked transaction after 2.5 seconds. JavaScript uses one 2.2-second deadline for lock acquisition, content, provider headers and bodies, callbacks, and final writes. The database deadline includes commit. A process stop or connection failure can lose a push. Recovery keeps the intent as unknown and never sends it again.

The runtime requires `COMPANION_PUSH_ENABLED=true` and `COMPANION_PUSH_DATABASE_URL`. Production must use a dedicated database login, a direct/session connection with verified TLS (`sslmode=verify-full`), PostgreSQL 17, and explicit reviewed privileges. A transaction pooler with unsupported session settings is insufficient. The process refuses missing configuration. Production provider URLs are fixed Expo HTTPS endpoints. `EXPO_ACCESS_TOKEN` is a server secret when the project enables Expo push security. `SANITY_PROJECT_ID` and `SANITY_DATASET` select the same Checklist content source. Never log environment values, tokens, installation proofs, or provider request bodies.

Migration `20261101042015_companion_push_worker_session_lock.sql` creates the dedicated `companion_push_worker` role with NOLOGIN and NOBYPASSRLS. It grants the worker's exact query privileges and RLS policies. Lock-only tables reject UPDATE through restrictive policies, including with fabricated JWT claims. The private postgres-owned `lock_session_authorized` helper locks the exact Auth session and checks its current authorization in the same transaction. The worker has no direct Auth table grant or service_role membership. It can read complete enrollment and profile rows. The migration also removes accessible PUBLIC SECURITY DEFINER execution outside the required helpers. It retains API-role access and records added ACL entries in a private RLS table for rollback. It fails if any other privileged function remains callable. Audit effective PUBLIC privileges again on the target database before separate LOGIN enablement. Test the exact login before enablement.

Verify effective Auth maximum lifetime and inactivity limits from the server. Put their exact values in `maximum_seconds` and `inactivity_seconds`. Zero means a verified unlimited setting. It is not a fallback. Record `policy_verified_at` and a bounded `policy_valid_until`. Refresh the record before expiration. Missing or expired verification fails closed. Enrollment has no foreground lease.

Verify the entire Expo project budget, including the unchanged social and learn senders. Set `provider_project_per_second`, `other_senders_reserved_per_second`, `companion_per_minute`, `receipt_per_minute`, `aggregate_verified_at`, and a bounded `aggregate_valid_until`. The worker uses the residual per-second capacity, a separate per-minute cap, and a shared rejection backoff. The configured reservation does not enforce limits on the other senders. Aggregate hosted capacity remains unproved until their actual traffic and limits are checked. Do not enable dispatch with an unverified reservation.

Set `dispatch_not_before` to the verified enablement instant. Earlier due events are consumed without a send. Enqueue records each due event once. Each reminder/installation identity is unique. Renewal, token rotation, restart, and schema reapply cannot create another identity. A disabled or suppressed event cannot restart later.

Only an explicit HTTP 429 or a definite retryable ticket rejection permits a new send. Backoff is at least 30 seconds. The cap is at most three attempts. A lost response, invalid JSON, deadline, crash, or uncertain commit stays unknown. Receipt queries start after 15 minutes. Missing receipts remain pending. Receipt queries stop after 24 hours. Neither tickets nor receipts prove device display. Expo can deliver more than once. Provider acceptance cannot be cancelled by this service.

Stop the service before rollback. Run the MOBILE rollback, which WEB mirrors exactly. It disables settings, revokes credentials, and preserves suppression/attempt identities. Apply older rollback scripts only after this script, in reverse migration order. Reapply does not restore execution or credentials. Never delete private tombstones as a restart procedure.

Local fixtures require the owned database port 63611 and provider port 63615. They accept only synthetic tokens. Fixture settings do not qualify production settings. The tests use normal Auth, real JWTs, Postgres, RLS, Cron, and the authenticated action handler. They do not perform real Expo, APNs, FCM, hosted, model, or native operations.

## Node host adapter

`node-adapter.mjs` starts one unchanged supervisor cycle. It requires `COMPANION_PUSH_ENABLED=true`, a separate `COMPANION_PUSH_OPERATOR_SECRET` of at least 32 characters, and a verified-TLS URL for the dedicated `companion_push_worker` login. A direct connection uses that exact username. A shared Supabase session-pooler connection uses `companion_push_worker.<project-ref>` on an `aws-<number>-<region>.pooler.supabase.com` host and explicit port 5432. The project reference must contain exactly 20 lowercase letters. The tenant-qualified form is refused on transaction port 6543 or on another host. The same pinned CA and full certificate and hostname checks apply to both connections. No paid IPv4 add-on is required for the shared session pooler. It rejects fixture environment settings. It forwards only the dedicated database URL, the existing Sanity settings, the optional Expo access token, and fixed Deno settings. Worker stdout and stderr are discarded. HTTP responses contain only a fixed boolean result. The operator secret is not forwarded to Deno.

The Node process creates an owned POSIX process group. Its 110-second deadline includes package verification and cache preparation. It sends SIGKILL to the group on timeout, request cancellation, SIGTERM, SIGINT, Node exit, spawn failure, or supervisor exit. The proposed Next route has a separate 180-second function limit. The existing supervisor still selects at most 20 operations. Its child limit remains four seconds. The worker's 2.2-second JavaScript and 2.5-second PostgreSQL limits remain unchanged. An interrupted intent remains unknown and cannot authorize resend.

The HTTP handler returns 504 when the shared deadline expires, or 499 when the request is cancelled. It releases the busy guard at that response. Preparation checks the same signal before each stage and before process creation. The preparation task retains its temporary-directory ownership until pending file work settles and cleanup finishes. A slow filesystem cleanup does not extend the HTTP deadline.

Run `node supabase/workers/companion-push/prepare-runtime.mjs` from the application root before a deployment build. This separate command downloads Deno 2.9.8 Linux x64 and checks both the official archive and binary hashes. It stages frozen dependencies under `.runtime/linux-x64`. A macOS arm64 preparation host also downloads the pinned local runtime to prepare the cache. Large binaries and caches are ignored by git. An ordinary `npm run build` does not download a runtime. The proposed Web patch sets a deployment build command that performs preparation first. Root must verify the complete function size after its Next build.

The preview-only readiness route requires `VERCEL_ENV=preview`, `COMPANION_PUSH_READINESS_ENABLED=true`, and the operator secret. It does not need a database URL or provider token. Its fixed Deno fixture creates a child and grandchild. Node kills their group and checks that all three processes are dead. The response contains only the version and a cleanup boolean. Both the route and its configuration remain disabled by default. Local macOS fixture results do not prove Linux or Vercel execution.

Run the Node tests with `COMPANION_TEST_DENO` set to the prepared local pinned executable. A missing runtime fails the tests. Run `node check-package.mjs` from this directory to verify both prepared package manifests and their refusal controls. `role-and-session.test.ts` is a separate local SQL test for root's later lease. It requires project `unify-companion-push-vercel-r2` and database port 63621. It temporarily enables a synthetic local worker login, uses the actual role, checks allowed and denied queries, and observes three real session-lock orders. It refuses to connect without that lease. It does not start resources or install a schema.

The five files under `content-source` are the exact local import closure of the reviewed Web RAG helper at fff4a93ae58c9505f166b2188f7456e7435dc824. The required Mobile baseline lacked that helper. The worker imports this copy so both source mirrors use the same content rule without adding or modifying an Edge Function.

## Fixed database trust

The worker reads only the packaged `supabase-prod-ca-2021.crt`. It verifies SHA-256 `700723581420dd1ac98fd7e9ac529f0ef210eadcaf87fc868a3ad7d114c2f3b7` before creating a production connection. Postgres.js receives `ca` and `rejectUnauthorized: true`. Its normal TLS hostname check remains active. No request or environment value can select a CA path. The local test-only connection exception still requires the existing fixture flag and exact fixture host/port. No insecure production TLS option exists.

`deno.lock` is tracked explicitly despite the application's general ignore rule. Dependency preparation and runtime verification require that exact frozen file. `database-tls.test.ts` checks the production options. `tls-driver.test.ts` uses a synthetic local TLS server on the leased port 63624. It accepts a trusted fixture certificate, rejects that fixture under the fixed production CA, and rejects a wrong hostname. This proves local driver handshake behavior. It does not prove a hosted database connection.

`rollback-and-privileges.test.ts` requires the same local SQL lease. It verifies that rollback and reapply retain exact unknown deliveries, attempts, events and revoked enrollments. It also checks that the unchanged SQL validator rejects a DST gap and a mismatched wall/instant tuple. The local database has old time-zone data. Client tests with simulated device rules are separate from hosted upgrade proof.
