## 3. Defects, ranked by consequence

1. **Deadline-sheet evidence is stale, and the current chip/height fix is unverified** — `.design/evidence/checklist2-deadline-sheet-2026-09-03.png` flagged by the task brief as pre-dating a shortened-chip fix (90d/30d/7d) and a reduced sheet height. No fresh capture proves the fix actually resolved the overflow it was meant to fix. Does not block ship on its own (the *reported* fix addresses the *reported* problem) but the reviewer cannot confirm it — re-capture before sign-off. **Not a hard blocker, but should gate final approval.**
2. **"Later" horizon interleaves dated and undated items without visual separation** (`checklist2-later-with-deadline.png`): "Study permit expires · Nov 12 · in 70 days" sits directly above "Explore an event" with only a bucket tag. Both are legitimate per `buildHorizonRows` sort (dated-before-undated, `checklistHorizons.ts:92-97`), but visually the two rows look like peers, which weakens the "time orders the list" story DESIGN.md leads with. Not a blocker; a content/hierarchy polish item.
3. **Offline and full-Dynamic-Type states have code but no rendered evidence** — DESIGN.md's acceptance criterion "All states above render on the simulator with real data shapes" is only partially demonstrable from the supplied screenshots. Given the code path exists (`index.tsx` empty/caught-up states, `DeadlineSheet.tsx` permission-denied path), this reads as a documentation/capture gap rather than a missing feature — but it is exactly the kind of gap the AC exists to catch, so it should not be marked "met" yet.
4. **Undated "Do now" items still lack a hard action verb** — "Apply for Canadian citizenship if you have met the 1,095-day physical presence requirement as a PR" is unchanged copy from baseline; only the surrounding chrome (countdown, "Set a date") changed. Minor, does not block; the reworked structure compensates for it.
